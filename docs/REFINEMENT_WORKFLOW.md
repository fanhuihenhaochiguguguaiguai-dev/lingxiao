# 凌渊精修工作记录与复用流程

本文件记录可复用的处理依据、验证步骤与结果；实际模型是否达到人物照片的美术质量，需要查看真实渲染并验收，不能由脚本自动判定。

## 问题与共同根因

1. 额前头发像尖块，后发缺少流向：旧发束由少量规则形状组成，没有细分的发束层次，也缺少沿头发方向的中段变化。
2. 眉毛像黑色实心片：与旧发束一样，使用单一宽面近似细密的条状细节。
3. 颈部颜色突变和局部穿插：旧颈部与新头部自带的颈部网格重叠。腰间、衣袍和盔甲之间也可能有类似的部件重叠，应先确认几何来源和骨骼绑定，再局部处理。
4. 发冠、肩甲、衣摆和长枪仍有明显几何简化：这些也是“少量粗结构代替细节”的同类问题，但形态与绑定位置不同，不能把一套发束参数直接套到所有部件。

## 顺序与判断依据

1. **先定位**：对照用户原画及质量示意图，检查正面、侧面、背面，找出对轮廓和面部影响最大的缺口；识别旧部件与新部件的连接关系，保留未修改的来源。
2. **再做一个代表**：在独立候选中修正最高精度层的额前发束与重复颈部；通过实际渲染查看层次、遮挡和接缝。失败则调整参数或保留原版，不能盲目复制。
3. **最后复用**：仅在代表结果满足本轮客观检查时，将相同的部件筛选、绑定与导出方法应用至其他 LOD；各层分别检查面数、骨骼和浏览器加载，再检查动作和移动是否退化。
4. **记录验收**：将可重复的技术检查与视觉质量分开记录。软件能够加载、可以控制，只能说明相应功能通过；与用户照片是否相当需要实际视觉验收。

## 自动化边界

- `tools/refine_hair.py` 只处理名称和几何范围匹配的现有工作稿，找不到预期部件时停止，防止误删其他对象；使用 Blender 候选文件和版本记录，不覆盖原项目源文件。
- 当前母版已经应用本轮修复；若需要重现，可先从 Git 历史的修复前提交恢复一份临时输入，并通过 `LING_SOURCE_BLEND` 指向它。先运行默认代表模式，审看 `/tmp/ling-hair-front.png` 和 `/tmp/ling-hair-side.png`；再运行 `LING_PASS=all` 处理三个 LOD。
- `tools/validate_refinement.py` 从实际导出生成 `dist/model-stats.json`，网页只需读取这个小文件，不再预先下载所有模型；移动尺寸默认加载 LOD1。
- `tools/validate_refinement.py` 检查 GLB 格式、各 LOD 的网格和动作、骨骼与实际蒙皮；还要结合 Blender 渲染及浏览器控制测试。
- 面部神韵、发丝真实感、动态穿模、长枪雕纹及安卓真机性能不能靠这些静态检查判定，应保留未通过或未验证状态。

## 本轮结果与继续顺序

代表层先完成额发与颈部处理，确认能形成独立发束并去掉重复网格，再复制到另外两档；三档动作、权重和网页操作已通过技术检查。新发束仍有规律、稀疏与贴头皮问题，脸型及材质也没有达到质量示意图；下一轮应优先改善头部造型和发际线，然后处理衣领／肩甲接缝，最后处理腰饰、裙摆和长枪。不要因技术检查通过就跳过这些美术问题。
