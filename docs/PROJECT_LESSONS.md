## 如何分析和选择下一步

1. 固定参考图、角度、灯光和姿态，保存实际渲染基线。角色外观以最初确认的银白发设定为准，技能图只补充动作与特效；不把模糊增强结果当成真实设定。
2. 先找范围广且可验证的上游原因：如错误坐标、共享可变状态、导出遗漏或素材引用不一致。选一个代表部件对照实验，通过后再扩展。
3. 共性技术共享，角色脸型、发型、服装和技能造型分别处理。程序化生成用于可控的重复结构；面部神韵、整体比例和艺术质量仍要逐角度观察。
4. 按真实收益、影响范围、成本及回归风险排序。候选没有可观察改善时，保留原因和结果，回退该候选，不把增加面数、粒子或 Bloom 视作质量提升。
5. 分开进行技术、艺术与历史问题回归：能加载只证明资源可解析，命中事件只证明测试场景的判定，不能替代对战平衡、人物相似度、专业听感或手机实测。

## 失败经历与预防

- **模型能导入但外形仍简陋。** 原因是技术加载检查无法衡量原画神韵。今后必须保留原图与真实 3D 多角度对照，技术、艺术两项分别验收。月璃五官、后发、裙装和鞋靴当前仍未达标。
- **程序化裙片、袖片悬空或交叉。** 旧候选使用独立坐标，未与人体及衣层建立正确连接，候选已撤回。先以实际表面拟合并看侧背面，之后仍需动态碰撞验收；静态贴合不足以证明不穿模。
- **发束侧面悬浮。** 射线未命中时错误采用固定前方坐标；改为保留连续路径，仅命中时贴合。见 `qingli-production-lessons.md` 和最新固定角度渲染。
- **只修改 Shape Key 而导出顶点没有相应变化。** 基础网格与变形坐标需要保持同步，直接比较最终 GLB，而非只检查脚本是否执行。
- **跑步脚部悬空与衣袍穿插。** 旧候选未通过，不作为成熟动画复制；先检查接触目标是否在腿长范围，再检查实际鞋底、重心和衣物。当前轻量接触求解不等于全身 IK 或衣服碰撞已经完成。
- **冰晶生成出现黑色扁片，冲击环反向缩回。** 原因分别是单轴缩至零和将扩张与消散绑定同一包络；改为三轴生长、独立控制扩张及透明度。
- **共享材质和时钟造成多实例串扰。** 只共享不可变几何，材质、动态缓冲、时间、音频、位置、命中独立；回收时不得释放仍被其他实例使用的资源。
- **触摸防重复误吞鼠标输入。** 分别识别真实触摸及后续独立鼠标输入；模拟双指时还需确认释放的是正确指针，见 `verification/moonfall/touch.json`。
- **软件图形任务并发导致截图超时。** 本轮单独运行后端验证通过；并发软件渲染不代表手机帧率或硬件性能。

## V3.1 新经验：活动场景、制作母模和证据有效性

- **文件命名／网格定义不等于实际场景。** 三个正式 LOD 文件都挂接全部三档头发；单看存在 `Hair_Lod1` 或静态统计会漏检。修复活动场景连接后，二进制、骨骼与动画不变，同视角绘制调用 59→53、三角形 91094→60638。今后必须遍历活动场景，断言恰好一个匹配的头发档位；导出显式选择、可见和可渲染过滤。
- **不要把假设写成历史根因。** 隐藏对象残留选择是可疑机制，但当前探针没有复现；已证实的是错误挂接及缺少排他检查。修复针对已证实数据，预防覆盖风险，不虚构原始操作过程。
- **高模只负责制作。** 独立离线 Multires 高模实际烘焙法线／AO，运行保留原笼、UV 和眨眼；导出排除 `offline_only`，检查贴图真正被材质引用。成功烘焙仍不代表脸部神韵通过。
- **前面正常也可能侧面失败。** 新前发 45° 出现宽扁尖块，已拒绝且默认禁用实验；不能据正面一张图批量推广至所有 LOD 或另一人物。
- **截图前重置会清掉要验证的状态。** 闭眼测试曾在 Blink=1 后重置角色，截图无效；改为先重置、再设置，并读取实际网格权重验证。记录测试本身的错误及修正，不能沿用失效证据。
- **资源减少与流畅度分别验证。** 此次实际录像依然缓慢，软件渲染计数下降不能替代安卓帧率实测；未使用的二进制未删除，也不能宣称下载缩小。
