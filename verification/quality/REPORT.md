# 人物与三技能：质量基线及增量修复

## 范围

本轮遵循此前用户对“人物平台网页”的明确更正，修改同一 Three.js / WebGPU 优先的技能展示工程。该页面不是带敌人和判定的《曜境》对局，也没有真实安卓设备；本报告不把软件浏览器结果称作游戏实机验收。

## 因果和证据

| 分类 | 观察与根因 | 范围与证据 |
|---|---|---|
| 同类型共性 | 一、二技能复用同一简化龙体，三技能使用相似的管状龙身；内部流动层次稀少。 | 实际基线图 `before-skill1.png`、`before-skill2.png`、`before-skill3.png` 和源码中的龙身网格。轮廓问题并非仅由曝光造成。 |
| 模型材质共性 | LOD1 共 16 种材质，只有 1 种带法线贴图，只有 1 种带金属粗糙度纹理；多数为常数 PBR。 | `glb-audit.json` 检查材质引用；不能仅凭此判断所有材质的实际观感。 |
| 独立模型问题 | 脸型与参考差距大、手及袖遮挡、肩甲与长枪形体简化。 | Blender 真实画面及既有 `verification/REPORT.md`；形态与权重需要专项精修。 |
| 渲染假设，已实验 | 高清档打开全局动态阴影可增加接地阴影，但人物画面绘制调用 67→128，技能画面均增加 61 次。 | `before.json` 与 `experiment.json`；因此未把该实验合入高清档。 |
| 独立脸型实验，未采用 | 将既有三个脸型形变增大后，真实 Blender 对照看不到足以接近参考的改善。 | `face-before.png`、`face-candidate.png`；没有覆盖母版和 GLB。 |
| 尚未证实 | 全局曝光、材质色彩空间、动画权重、透明排序是否是各缺陷的主要根因。 | 需分项对照、更多视角和硬件测试；没有当作已证实问题批量修改。 |

## 优先级与实施

下表用 1–5 的主观相对分值代入 `(视觉影响×影响范围×成功可能)÷(时间成本×回归风险)`；只是本轮排序工具，不是测量数据或成功概率保证。

| 任务 | 影响 / 范围 / 可能 / 成本 / 风险 | 分值 | 决策 |
|---|---|---:|---|
| 共享龙体流光层次 | 4 / 3 / 4 / 2 / 2 | 12 | 先在一、二技能实际渲染，对过宽样本减弱后应用于第三技能；保留独立配色、动作轨迹和时间轴。 |
| 全局阴影 | 2 / 4 / 5 / 3 / 4 | 3.3 | 实测调用成本高，高清档不采用；极致档原设置保留。 |
| 人物材质纹理 | 5 / 3 / 2 / 4 / 4 | 1.9 | 缺少有效烘焙和对应细节资源，留待专门制作，不用随机噪声冒充。 |
| 脸部结构 | 5 / 3 / 2 / 5 / 4 | 1.5 | 已试现有形变但收益有限，未修改已保存的角色资产。 |

实现了一个参数化的真实三维窄带组件 `skill-src/src/energy-ribbons.ts`，随各技能自己的龙身空间曲线和时间变化；共享几何合并为单次绘制，采样结果在同一更新内复用。它增加了局部能量层次，**不等于完成龙首精雕或高品质视觉验收**。宽幅初稿造成遮挡，已减少宽度与强度；`ribbon-skill1.png` 是未采用的早期样本。

## 验证和未完成

- TypeScript 严格构建通过；三档 GLB 引用、蒙皮、基础动画结构检查通过；Blender 实际打开母版检查 58 根骨骼及行走时发束顶点变化。
- 软件 WebGL2 下三个时间轴分阶段采样、角色骨骼变化及技能切换通过；暂停、逐帧、慢放、循环及模拟横屏已由 `test_skill03.py` 回归。`timeline.json` 与 `skill03-controls.json` 为测试记录。
- 软件 WebGPU、强制 WebGPU / WebGL2 Bloom、WebGPU 不可用时的 WebGL2 回退均成功；见 `skill03-backends.json`。这不代表实体手机的 GPU 兼容。
- **V2/V3 目标未完成。** 角色脸、发、服饰、武器和材质没有达到参考；三技能核心造型、爆发和动画仍明显简化。未完成独立雕刻、UV、烘焙、PBR 纹理、握枪及穿模修复。
- 未录制完整连续对比视频；现有证据是固定时刻渲染和程序化时序检查。未验证真实手机、实际对局镜头、伤害冷却、硬件帧时间及稳定性，不能宣称实机画质提升或 V3 验收通过。
