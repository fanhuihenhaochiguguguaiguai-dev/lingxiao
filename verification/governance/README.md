# V2.0 共性治理：本轮增量与验收

基线：`a6f9570c6abf3fe8724c606709b39de6f460a697`，原网站发布版本 V22。保留正式入口、场景、人物、摇杆、跳跃、六技能按钮、镜头与声音／画质菜单。当前仍是角色与技能展示工作稿，未达到整个人物原画还原或电影级艺术标准。

## 已确认问题、修复与证据

| 优先级 / 现象 | 证据及已确认原因 | 本轮修复 / 预防检查 |
| --- | --- | --- |
| P0 暂停后再施法，实例停在第 0 帧 | `before-states.json` 中 `paused:true, latestAge:0`；释放入口只恢复人物播放标记，未恢复实例调度 | 释放时恢复实例调度与音频；`after-states.json` 新实例年龄正常推进。 |
| P1 暂停音画分离 | 暂停后技能年龄变化为 0，音频时钟仍推进约 1.29 s；原暂停只控制模拟 | `InstanceAudio.setPaused` 同步 AudioContext，冻结播放位置；后测音频和模拟均无推进，恢复后继续。 |
| P1 月璃中断施法后手腕残留 | 右手腕与绑定姿态相差约 0.10448 rad；施法修改手部，但共用重置掩码漏掉手部 | 补齐受控通道，后测误差为 0。没有套用统一脸型或改变角色外观。 |
| P1 训练命中脱离特效 | 旧凌渊大招在 1.0 s 命中，冲击环从约 4.85 s 才形成；原因是三技能沿用了早期统一占位窗口 | 注册表为各技能定义范围与阶段；大招使用实际扩张公式，目标在约 5.7167 s 被冲击范围覆盖时命中。一技能使用实际龙首扫掠路径，避免固定点与视觉轨迹错位。 |
| P1 命中与音频事件缺少关联 | 凌渊原有声音只按演出阶段播放，没有按训练命中单独触发 | 保留演出音轨，复用已有授权素材补充每实例命中反馈；六技能十实例的目标 ID、实例 ID 和命中／声音时间一致，见 `instances.json`。 |
| P1 单个专属音频缺失中断整个预载 | 原顶层 Promise 批次一项失败即退出后续批次，影响其他技能 | 每个文件独立失败，继续解码其他文件；注入 404 后其他 65 个可用，重试后补齐 66 个。见 `lifecycle.json`。 |
| P2 生命周期历史时间单位混用 | 原创建时间来自 `performance.now()` 毫秒，结束时间来自模拟秒 | 创建／结束均使用模拟秒，另存 `createdWallTimeMs`。三轮到期记录检查 11.4 s 时长，取消也记录结束时刻。 |
| P1/P2 衣片锯齿与长发剪影不足 | 旧衣片按面中心选取，边界呈阶梯；旧后发基本齐腰截断。固定相机对照见 `art/` | 两件衣片按实际表面及接缝平面重建，保留 3 mm / 1.8 mm 厚度和蒙皮；长发样板沿后侧衣层静态避让，使用原有头发骨骼。 |

后台恢复代码对未初始化实例增加了保护。模拟早期切后台未复现旧异常，因此只记为时序风险防护，不宣称已复现 P0。角色加载失败后的保留原人物、重试与缓存行为本来已有实现，本轮注入 503 验证通过，没有重复开发。

## 必要解耦与所有权

- [`motion-profile.ts`](../../skill-src/src/motion-profile.ts)：从角色类型布尔值迁出步幅、支撑比例、抬脚、摆臂、重心和施法风格。保留原数值与实测骨长求解，未凭配置迁移宣称动作自然度已提升。
- [`skill-registry.ts`](../../skill-src/src/skill-registry.ts)：集中六个技能的生成器、更新、时长、事件、训练范围及释放方式；`SkillInstances` 共用生命周期、去重和对象池，不再在多个方法各维护一套技能名称分支。
- 动态缓冲、材质、时钟、位置、命中和声音仍属各实例；月系借用的不可变几何由原模块保留，其专属释放函数只释放自身动态资源。`clear` 也计入释放统计。音频停止时显式断开 source / gain / panner。
- [`studio-world.ts`](../../skill-src/src/studio-world.ts) 的事件标记 `scope:'training'` 并携带位置。保留既有事件名与字段，当前没有生命值、正式伤害、击退或战斗裁决。
- `CharacterAssets` 保留合并请求和每角色一份缓存，增加内部状态检查；正式页面仍是 Three.js + TypeScript、WebGPU 优先及 WebGL2 回退。根页面跳转 `/skill/`，当前主入口不使用 PlayCanvas；历史引擎资产保留，未进行迁移。

## 代表样板与艺术边界

`art/before-*.png` 与 `candidate-*.png` 是同一灯光、正交投影、姿态和视角的真实 Blender 渲染。新衣片首先出现侧面缺口，原因是严格裁切缩窄了原来依靠越界面片连接的区域；调整至与相邻袖片实际重叠后重新检查侧面，不推广失败候选。

当前采纳的是衣片边界修整及后发长度／层次的有限增量。身体与脸部 POSITION 字节保持不变，没有再做通用眼睛放大或批量套脸；骨骼数不变，运行 GLB 与母稿导出一致，见 `model-provenance.json`、`assets.json`。模型约从 10.10 MB 增至 10.88 MB，后发合并为一个材质批次。新增结构是否值得其成本，以真实画面与后端运行检查衡量，不以顶点数量衡量。

**尚未达标：** 两个人物的原画神韵与整体精致程度，月璃的后发分束仍规整，完整发饰、衣装剪裁、鞋靴及高级肤眼材质仍需独立艺术制作。后侧表面避让是静态约束，原有弹簧不是完整衣发碰撞；动态截图不构成不穿模或全身 IK 验收。凌渊脸型与武器外形本轮没有重建，沿用之前真实基线并保留未达标状态。

## 技术与性能证据

- `npm --prefix skill-src run build`：TypeScript 和构建通过。
- `instances.json`：六技能各 1/3/5/10 次即时释放，独立对象／时钟／出生锚点，跑跳施法、池复用；每技能十个实例分别命中，声音与命中事件时间一致。
- `before-states.json` / `after-states.json`：暂停、暂停中施法、手腕姿态的前后对照。
- `lifecycle.json`：加载 404 / 503 的恢复，训练爆发时序；三轮十实例回收后 `renderer.info` 均回到 200 个几何分配、18 个纹理，活动时为 208 / 18。此计数稳定不等于总内存零泄漏或长时间稳定性通过。
- `backends.json`、`backend-*.png`：最终模型与十冰龙在桌面软件 WebGL2 / WebGPU 下的真实画面、Draw Calls、三角形、观察帧间隔和可用时的近似 JS 堆数据。软件路径有主动 90 ms 节流，不能视作硬件渲染速度。
- 同为高画质、十冰龙的几何计数对比：Draw Calls 283 → 284，三角形 962137 → 988413（约 +2.73%）。软件后端本轮观察帧间隔约 2.34–3.52 s，未呈现流畅效果；旧版本没有同条件帧间隔数据，不能报告 FPS 提升。
- `character/`：最终 GLB 在网页中的眨眼、跑步接触控制、切换与十实例回收后重新显示龙首；外观和自然动作仍需艺术验收。
- `touch.json`：CDP 横屏双指模拟，3/5/10 次施法数量、音频事件与实际位移；沿用原控制布局。真实手机触控未验证。

**真机未验证。** 安卓硬件帧率、帧时间、内存、长时运行、音频物理延迟与专业听感未通过验收。已有音频素材和混音参数未重制，原离线响度报告只在其有效范围内继承，不把源文件存在或桌面运行当作高级音效验收。

## 后续最小增量顺序

1. 在现有训练事件旁定义正式攻击事件与受击对象适配器，保留训练显示路径。
2. 先在单个目标验证生命值、伤害去重、阵营／无效目标及受击恢复；不同时开发 AI 和地图。
3. 接入一个角色的普攻与连击，复用输入、动作分层和技能时钟，再适配第二角色的独立动作。
4. 增加一个敌人的基础战斗 AI，验证双方命中、移动和死亡／恢复流程。
5. 用少量可破坏物验证同一攻击事件的环境反馈与破坏阈值；通过后再考虑 1v1 场景，联网另行评估。

本轮没有增加这些战斗功能、角色大厅、擂台、地图或 APK。下一轮美术应以一个真正接近原画的头部样板为门槛，未通过时停止批量套用参数；技术修复与人物个性精修继续分别验收。
